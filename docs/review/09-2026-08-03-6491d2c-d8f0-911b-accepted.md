## Item 1 — ProbeCache methodology (dagmar-d8f0)

### Build / API verification

- `GOWORK=off go -C .dagger build ./...` → **exit 0**; `go vet ./...` → **clean**.
- `ProbeCache` relies on `dag.Container().WithMountedCache(path, *CacheVolume, opts ...)`. The generated signature is `WithMountedCache(path string, cache *CacheVolume, opts ...ContainerWithMountedCacheOpts)` — the `opts` are variadic, so omitting them uses the **default SHARED** sharing mode, exactly as the code comment intends. `"strings"` is imported. Compiles and vets clean.

### Methodology assessment — SOUND

The three-leg design (`write` → `readsame` → `readdiff`), run as **three separate `dagger call` sessions against one engine**, is a textbook positive-control + negative-control experiment, and it is the *right* experiment for the ADR-0008 §3 claim ("Dagger isolates cache by volume **name**"):

- **Positive control (`readsame`)** — reads the *same* name `…-A` and expects the marker. This rules out the null explanations "reads don't work" / "cache doesn't persist across sessions." Observing `MARKER_A` proves persistence + read-path correctness.
- **Negative control (`readdiff`)** — reads a *different* name `…-B` and expects empty. Observing `EMPTY` is the discriminating signal: if the engine did *not* key by name, `…-B` would leak `MARKER_A` (`LEAK` / "FALSIFIED"). It does not → name-keying confirmed.
- **Quiet strength — identical mount path.** All three legs mount at `/cache`. This *disambiguates name-keying from path-keying*: if the engine keyed cache by mount-path, `readdiff` (same `/cache`, different name) would see the marker. It sees empty, so the key is provably the **name**, not the path. The design is tighter than the commit message claims.

### The SHARED-default question — NOT a confound

The prompt flags the default **SHARED** cache-sharing mode as a possible confound. It is not, and using SHARED is in fact the *strongest* test configuration:

- `SHARED` / `PRIVATE` / `LOCKED` are **concurrency-access semantics** for a single named cache, not identity rules. They never merge two differently-named caches. The cache identity is the `CacheVolume` *name* by construction, in every mode.
- SHARED is the production default and the most permissive (allows concurrent sharing). Getting isolation *under the most permissive mode* is the hardest case to pass — so a pass here is maximally convincing, not suspicious.
- **Minor imprecision in the code comment** (F4): the comment says SHARED is "what makes the volume name the sharing/isolation key." That is not quite right — the name is *always* the key regardless of mode. This does not affect the (correct) result; it is a wording fix.

### The local-engine question — faithful analogue

Three local `dagger call` sessions → one local engine models **multiple kube-pod clients → one singleton engine** because the cache identity is computed **engine-side**. The client (local process or `kube-pod://`) only supplies the name over the engine's API; it carries nothing that changes the keying. So client *transport* cannot change name-keying. The analogue is faithful for the property under test.

### The topology-agnostic claim — a sound INFERENCE, slightly over-worded

See **F1** (the one substantive finding). Short version: the claim is **justified for the planned topology** but is an *inference from a path that was not exercised*, and the durable record (ADR-0008 Consequences) states it as settled fact. The inference rests on the assumption that production uses a **single, name-keyed cache store** — which ADR-0008 §3 does assert ("one shared cache store; Dagger isolates cache by volume name") — so the two together support the claim. But the kube-pod transport and an in-cluster engine were not directly tested; the commit's "in-cluster kind test available as Tier 2 but not strictly required" hedge is honest, and that hedge is what is missing from the ADR bullet.

The residual that ProbeCache **cannot** and does not claim to test — that the *controller actually allocates distinct names per Project* — is correctly fenced off in both the commit and the ADR bullet as a pure control-plane guarantee. That scoping is correct and is the load-bearing honesty check; it passes.
