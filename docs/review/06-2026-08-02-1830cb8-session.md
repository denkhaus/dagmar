### F-new. `[HOUSE]` (low) — the A1 validation test is integration-tagged, so the default `go test ./...` run never executes it

**Location:** `.dagger/internal/app/sandbox_integration_test.go`
(`TestBuildSandbox_validation_integration`).

`go test ./...` reports `internal/app  [no test files]` — i.e. the whole file is excluded by a
build constraint, so the new `TestBuildSandbox_validation_integration` does not run in the
default test tier. This is low-impact: the **pure validation logic** is already covered where
it counts (`domain/sandbox_test.go`, which runs by default — `internal/domain  ok`), and the
app-tier test's own comment notes it "needs no engine". But that is precisely the point — a
fast, engine-free seam-guard test sitting behind the integration tag will not catch a
regression in ordinary `go test`/CI.

**Recommend (advice only):** either (a) move the empty-image assertion to a default-run test
(it is engine-free, so it can live outside the integration tag), or (b) accept the current
placement and rely on `domain/` for the logic-level guard. Not a defect — a placement note.
